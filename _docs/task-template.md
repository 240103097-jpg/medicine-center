# Issue Refinement Template

## Goal
Describe in one or two sentences what should be true
when the task is complete.

## Acceptance criteria
- [ ] State an observable, testable result.
- [ ] Include relevant validation and error cases.
- [ ] Include relevant permission and boundary cases.

## Out of scope
List what this task does not implement.
Link to the issue responsible for deferred work.
If nothing is deferred, write "None".

## Constraints
- Identify relevant specification and architecture documents.
- State dependencies and implementation boundaries.
- Identify libraries to use and restrictions to follow.
- Specify relevant data, security and timezone rules.
